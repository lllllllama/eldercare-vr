PICO ElderCare VR/MR UI 设计分析

基于当前 Unity 项目源码、场景构建器、运行时 UI 控制脚本和已有首页截图整理。重点回答：项目现在有哪些 UI、它们如何流转、视觉风格是否适合老年康养 VR/MR，以及下一步怎么优化。

Unity 2022.3.62f3 PICO XR SDK release_3.4.0 uGUI + TextMeshPro + XRI UI World Space Canvas 生成日期 2026-05-24

结论概览

4首页模块：健康游戏、康复运动、VR旅游、场景视频
3核心 UI 层：全局入口、乒乓训练、康复训练
2.0-2.45m主要 UI 舒适观看距离，由空间放置脚本控制
MR-first入口和康复场景默认开启视频透视和空间感知
当前设计方向是成立的。

大字号、高对比、四模块入口、按钮面积较大，符合老年 VR/MR 的低认知负担需求。首页已有清晰的功能分区，乒乓和康复都可以从同一入口进入。

最大问题是风格和组件不统一。

全局入口、乒乓内置首页、康复面板分别由不同构建逻辑生成，尺寸、圆角、按钮状态、字体系统和文字层级并不完全一致，后续扩展容易变散。

导航判断

全局入口目前承担“产品总菜单”职责，两个可用模块直接加载独立场景，两个未完成模块以弱化色和“待接入”状态展示。这个设计对演示很友好，也能避免用户误入空功能。

设计项当前实现评价
字体入口使用动态中文系统字体；康复 TMP 使用 NotoSansSC-VF.ttf 生成 RehabChineseTMP。方向正确。建议统一到 TMP 字体资产，避免 uGUI Text 与 TMP 混用造成字重、描边和编码表现不一致。
字号入口标题 74/92，卡片标题 42/52，乒乓 HUD 52，康复标题 36-44。对 VR 可读性友好。入口和康复之间字号体系略分裂，应抽成规范。
卡片入口卡片 460x220 或 570x260，乒乓内置首页卡片更大，并有 hover lift、glow、scanline。视觉反馈丰富，但两套首页不完全一致，容易让用户误以为是不同产品。
状态未接入模块变暗并显示“待接入”；可用模块高饱和。状态传达清晰。建议加更明确的禁用说明或灰阶 icon，降低误点后的困惑。
空间感所有主要 UI 是 World Space Canvas，支持拖拽手柄条和摇杆导航。符合 VR/MR。需要继续实机验证不同身高、坐姿、房间光照下的可读性。

空间与交互分析

入口 UI

默认放在用户前方约 2m，高度相对 HMD -0.1m，并在启动 1.25 秒或 18 帧内持续重定位，减少刚进场时偏移。

训练 UI

乒乓 HUD 固定在世界空间，额外安装拖拽和摇杆导航。数据读数在面板背景上显示，适合边训练边扫视。

康复 UI

训练选择距离至少 2.45m，高度相对 HMD +0.08m；视频默认在用户右前方，支持拖动、缩放和重置。

控件/方式脚本依据用户体验判断
射线点击TrackedDeviceGraphicRaycaster、XRUIInputModule适合 PICO 手柄；按钮面积整体够大。
拖拽 UIWorldSpaceUiRayDragHandle 与 ComfortWorldSpaceUIPlacer高级但必要。建议给拖拽条加更明确的视觉 affordance，例如“可移动”小图标。
摇杆导航WorldSpaceUiThumbstickNavigator对手抖或射线瞄准困难用户很友好。
乒乓调速右手 A/B 控制，屏幕 +/- 按钮默认隐藏减少视觉噪声，但需要在 HUD 上清晰说明“下一次发球生效”。
返回路径康复和乒乓都有返回主入口能力基础闭环完成。建议所有二级场景的返回按钮位置和文案统一。

主要风险与建议

优先级问题建议
高UI 构建分散在多个 Builder 和运行时控制器里，入口、乒乓、康复各有一套视觉规则。沉淀 ElderCareUiTheme 或 ScriptableObject：颜色、字号、圆角、面板距离、按钮尺寸、拖拽条样式统一配置。
高代码中部分文件在普通读取时出现乱码风险，README 已明显有编码损坏迹象。统一仓库文本编码为 UTF-8，检查 README 和 C# 字符串，避免中文 UI 在构建机或编辑器里异常。
中入口中健康游戏和康复能进入，另两个模块禁用但仍是大卡片，可能被用户反复尝试。禁用卡片保留展示价值，但增加更明确状态：例如“即将开放”，并在点击时只更新底部状态，不触发场景尝试。
中康复面板同时包含用户目标、动作状态、Debug 文本，老年用户可能看到过多技术信息。把 Debug 改为开发者模式或长按显示；主界面只保留动作、进度、倒计时、安全提示。
中乒乓 HUD 数据多且全为同等字重，扫视层级不够。把“命中率/当前速度”提升为主读数，发球/漏球/旋转降一级，减少运动中阅读负担。
低首页有科技星点、扫描线、发光效果，视觉上偏“科技演示”。康养产品可以保留科技感，但建议加入更温和的形态：更多留白、低饱和背景、降低闪动幅度。

建议的下一版 UI 结构

落地顺序

先统一主题参数和中文字体，再把入口卡片、返回按钮、面板背景、拖拽条抽成可复用 prefab。Builder 只负责实例化和事件绑定，运行时脚本只负责状态切换。

这样后续接入 VR 旅游和场景视频时，不需要复制一套 UI 风格，也能降低 MR 实机调试时的变量数量。
